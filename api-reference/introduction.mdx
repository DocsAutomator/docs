The DocsAutomator API lets you generate documents programmatically, manage automations, and control e-signature workflows. Use it to integrate document generation into any application.

<Info>
The API works with both **Google Doc** and **PDF template** automations. The same `POST /createDocument` endpoint generates documents from either template type -- the automation's configuration determines the output.
</Info>

## Base URL

```
https://api.docsautomator.co
```

## Authentication

All API requests require authentication. Pass your API key using either method:

```bash
# Bearer token (recommended)
Authorization: Bearer YOUR_API_KEY

# Alternative header
X-API-Key: YOUR_API_KEY
```

<Info>
Find your API key at [app.docsautomator.co/settings/workspace/api](https://app.docsautomator.co/settings/workspace/api). API keys are scoped to a workspace.
</Info>

## Quick Start

Create your first document in three steps:

<Steps>
  <Step title="Get your API key">
    Go to **Workspace Settings > API Key** in the DocsAutomator app.
  </Step>
  <Step title="Get your automation ID">
    Find the automation ID on the automation's settings page, or call `GET /automations` to list all automations.
  </Step>
  <Step title="Create a document">
    <CodeGroup>
    ```bash cURL
    curl -X POST https://api.docsautomator.co/createDocument \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "automationId": "YOUR_AUTOMATION_ID",
        "data": {
          "customer_name": "Acme Corp",
          "invoice_date": "2025-01-15",
          "total": "$1,500.00"
        }
      }'
    ```

    ```javascript Node.js
    const response = await fetch("https://api.docsautomator.co/createDocument", {
      method: "POST",
      headers: {
        "Authorization": "Bearer YOUR_API_KEY",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        automationId: "YOUR_AUTOMATION_ID",
        data: {
          customer_name: "Acme Corp",
          invoice_date: "2025-01-15",
          total: "$1,500.00",
        },
      }),
    });

    const result = await response.json();
    console.log(result.pdfUrl);
    ```

    ```python Python
    import requests

    response = requests.post(
        "https://api.docsautomator.co/createDocument",
        headers={
            "Authorization": "Bearer YOUR_API_KEY",
            "Content-Type": "application/json",
        },
        json={
            "automationId": "YOUR_AUTOMATION_ID",
            "data": {
                "customer_name": "Acme Corp",
                "invoice_date": "2025-01-15",
                "total": "$1,500.00",
            },
        },
    )

    result = response.json()
    print(result["pdfUrl"])
    ```
    </CodeGroup>
  </Step>
</Steps>

## Sync vs Async Mode

By default, `POST /createDocument` runs synchronously and waits for the document to be generated (up to 5 minutes). For high-volume or latency-sensitive workflows, use **async mode**.

### Sync mode (default)

```json
{
  "automationId": "abc123",
  "data": { "name": "Acme Corp" }
}
```

Returns `200` with the PDF URL when complete.

### Async mode

```json
{
  "automationId": "abc123",
  "async": true,
  "data": { "name": "Acme Corp" }
}
```

Returns `202` with a `jobId` immediately. Poll `GET /job/{jobId}` for the result:

```bash
curl https://api.docsautomator.co/job/YOUR_JOB_ID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Polling pattern:** Use exponential backoff starting at 2 seconds. Jobs typically complete in 5-30 seconds.

## Rate Limits

| Scope | Limit |
|-------|-------|
| Global | 2000 requests per 15 minutes per API key |
| Test email | 25 per hour per automation |
| Queue concurrency | Max 5 active jobs per workspace |
| Document creation | Never limited under 20 open requests, see below |

When you exceed a rate limit, the API returns `429 Too Many Requests`.

### Document creation requests

Most workspaces never meet this limit. It only protects the API when one workspace sends a very large number of requests at once. It applies to every request to `/createDocument`, including requests from the API, Zapier, Make, n8n, MCP and the in-app assistant. These requests do not count toward the global limit.

An open request is one that we have received and not yet answered.

- **Fewer than 20 open requests:** your request is always accepted, even when the API is busy.
- **20 or more open requests:** your workspace has an allowance of 120 requests, which refills by 5 a second. When the allowance is used up, the next request gets a `429`.
- **The API is busy:** when the API holds 100 open document requests in total, only the workspace with the most open requests gets a `429`.

### How to retry

A `429` from the document creation limit means that no document was created, so it is safe to send the same request again. A `429` from a connected service (see [Common 429 Causes](#common-429-causes)) can come after part of the work is done, for example after the PDF was attached to a SmartSuite record.

1. Read the `Retry-After` header of the response. It gives the wait in seconds.
2. Wait that long, then send the same request again.
3. If you send many documents, wait for some answers before you send more, or send `"async": true` so that each answer comes back at once.

## Error Codes

| Code | Description |
|------|-------------|
| `400` | Bad request. A parameter is missing or invalid, a connected account must be reconnected (code `SOURCE_ACCOUNT_DISCONNECTED`, see below), or the e-invoice or QR-bill data is invalid (code `E_INVOICE_INVALID` or `QR_BILL_INVALID`). |
| `401` | Unauthorized. The API key is missing or incorrect. |
| `402` | Payment required. The workspace reached its document limit, or its subscription is paused. |
| `403` | Forbidden. The connected Google or Airtable account may not open or edit the template, folder, base or field; the Google Drive is full; or the request uses something the workspace may not use, such as signing without an active subscription or approvers below the Business plan. |
| `404` | Not found. The automation, template, or record does not exist. |
| `429` | Too many requests. Wait the number of seconds in the `Retry-After` header, then send the request again (see below). |
| `5xx` | Server error, or a connected service failed or did not answer. Try again later, or contact support if it keeps happening. |

Errors from `/createDocument` are JSON with a `message`. Some also have a `code`. A `4xx` answer has the same status and code whether the request runs right away or waits in our queue.

### Common 400 Causes

- A required parameter is missing or invalid.
- `SOURCE_ACCOUNT_DISCONNECTED`: the Google, Notion or Airtable account connected to your workspace no longer works. The message says which account. Reconnect it in the DocsAutomator app under [Settings, Integrations](https://app.docsautomator.co/settings/workspace/integrations), then send the request again. Your API key is fine. It happens when:
  - Airtable or Notion refuses the stored refresh token, because the access expired, was revoked, or was granted again elsewhere. This is the most common case.
  - DocsAutomator has no Google access token it can use or renew, or Google refuses the connected account ("Invalid Credentials").
  - Airtable or Notion refuses the connection itself.

```json
{
  "message": "Error refreshing Airtable access token. Please visit https://app.docsautomator.co/settings/workspace/integrations and reconnect your Airtable integration. This will not remove any of your data mappings.",
  "code": "SOURCE_ACCOUNT_DISCONNECTED"
}
```

### Common 401 Causes

- Missing `Authorization` or `X-API-Key` header
- Incorrect API key

### Common 404 Causes

- Automation ID doesn't exist or belongs to another workspace
- No template configured on the automation
- Automation is inactive (set `isActive: true` via the API or app)

### Common 429 Causes

- Your workspace sent too many document requests at once (see [Rate Limits](#rate-limits)). No document was created. `Retry-After` is 10 seconds.
- More than 2000 requests per 15 minutes with one API key. `Retry-After` is the time until the window resets.
- Google, Notion or SmartSuite limited the requests of your connected account, after their own retries. `Retry-After` is 60 seconds.
- `/sendTestEmail`: the test email limit is reached (25 per hour per automation, 100 per hour per workspace, or 10 different recipients per hour per workspace). `Retry-After` is the time until the hourly window resets. This answer has the text in `error`, not `message`.

Every `429` has a `Retry-After` header with the wait in seconds.

## Webhooks

Configure a webhook URL on your automation to receive notifications after document generation. The webhook receives a POST request with:

```json
{
  "message": "success",
  "pdfUrl": "https://...",
  "googleDocUrl": "https://...",
  "webhookParams": { "orderId": "ORD-123", "recId": "recAbC123XyZ" },
  "additionalParams": { "orderId": "ORD-123", "recId": "recAbC123XyZ" }
}
```

Pass custom data through to webhooks using `webhookParams` in your `createDocument` request. It is returned under both `webhookParams` and `additionalParams` (identical content; the latter is kept for backward compatibility), together with the automatically included trigger record identifier — `recId` (Airtable, SmartSuite, Notion), `taskId` (ClickUp), or `rowNumber` (Google Sheets). Your own keys are never overwritten.

## E-Signatures

When an automation has e-signatures enabled and the template contains e-sign placeholders (`{{esign.signature_1}}`, `{{esign.date_1}}`, etc.), creating a document automatically starts a signing workflow. The response includes the signing session ID and signing links.

See the [E-Signatures](/api-reference/e-signatures) endpoints for managing signing sessions programmatically, or the [eSign guide](/features/docsautomator-esign) for setup instructions.
