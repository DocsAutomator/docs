The Notify Webhook action can start an AI agent. When a client signs or accepts a document, DocsAutomator sends the event to your agent, and the agent continues the work. For example, it updates your CRM, writes a note or files the signed PDF. You do not need to open a chat.

Two agents are built in:

- **Claude routine**: a Claude Code routine with an API trigger. Routines are available on the Claude Pro, Max, Team and Enterprise plans.
- **ChatGPT agent**: a ChatGPT workspace agent with an API channel. Workspace agents are available on ChatGPT Business and Enterprise.

An automation has one webhook. **Send to** in the card decides where it goes: **Webhook**, **Claude routine** or **ChatGPT agent**. To change it, pick another option. Nothing changes until you enter the new URL (and token), so a click alone loses nothing.

## Start a Claude routine

<Note>
  A Claude routine runs as a Claude Code task. Open [claude.ai/code](https://claude.ai/code) once and finish its setup before you create the routine.
</Note>

<Steps>
  <Step title="Create the routine in Claude">
    Open [claude.ai/code/routines](https://claude.ai/code/routines) and click **New task**, then **Set up manually**. Enter a name and the instructions for the agent. Tell it what to do with the event, for example: "The routine-fire-payload block holds a DocsAutomator event. When its event is esign.session_completed, write a short note with the signer, the date and the signed PDF link."
  </Step>
  <Step title="Add the API trigger">
    In the **Trigger** row, choose **API** and click **Create**. Claude shows the trigger URL and the token. Copy both now, because Claude shows the token only once.
  </Step>
  <Step title="Connect the routine in DocsAutomator">
    In the automation editor, open **Actions**, click **Add action** and pick **Webhook or AI agent**. Under **Send to**, choose **Claude routine**. Paste the URL and the access token. Each field saves when you leave it.
  </Step>
  <Step title="Send a test event">
    Click **Send test**. DocsAutomator sends a sample document and shows whether the routine accepted it. "Received. The routine started." means that the routine started once. You find the run in Claude under your routines.
  </Step>
</Steps>

## Start a ChatGPT workspace agent

<Steps>
  <Step title="Turn on agents and access tokens">
    A workspace admin opens **Workspace settings**, then **Permissions & roles**. Turn on workspace agents and **Allow users to create personal access tokens**. Both are off by default.
  </Step>
  <Step title="Give the agent its apps">
    In the agent, add the apps it needs under **Tools**, for example Airtable. Set the app's write actions to **Never ask**: a run that DocsAutomator starts has nobody to approve a write, so with **Always ask** it stops and waits. On ChatGPT Business, an admin may first need to set the workspace's plugin permissions to **Allow low-risk**.
  </Step>
  <Step title="Add an API channel">
    Add an **API** channel to the agent and save it. Copy the trigger URL.
  </Step>
  <Step title="Create the access token">
    Open **Access tokens**, click **Create**, choose the **Workspace Agents** scope and a validity period, and copy the token. ChatGPT shows it only once.
  </Step>
  <Step title="Connect the agent in DocsAutomator">
    Add **Webhook or AI agent** and choose **ChatGPT agent** under **Send to**. Paste the URL and the access token. Each field saves when you leave it.
  </Step>
  <Step title="Send a test event">
    Click **Send test**. The agent's answer appears in the agent's ChatGPT conversation.
  </Step>
</Steps>

<Note>
  Every ChatGPT access token expires. When it does, the agent stops starting. Create a new token in ChatGPT and paste it into the card. Agent runs also use your ChatGPT workspace's credits, so keep credits available.
</Note>

## When the agent starts

The agent starts once per document:

- **With signing or acceptance on:** when the document is signed or accepted. Each signer step, reminder, decline or expiry does not start it.
- **Without signing or acceptance:** when the document is created.

The card shows which one applies, for example "Starts when a document is signed or accepted." If you switch signing on or off later, the agent follows the new setting. An API request that skips signing for one document starts the agent when that document is created.

## What is sent to your agent

DocsAutomator sends the token as the `Authorization` header (`Bearer <token>`). For a Claude routine it also sends the `anthropic-version` header. The agent receives the event as one text value: `{"text": "..."}` for a Claude routine and `{"input": "..."}` for a ChatGPT agent. The text is the event as JSON:

| Field | Meaning |
|-------|---------|
| `event` | `esign.session_completed` (signed or accepted) or `document.created` |
| `closeType` | `signature` or `acceptance` |
| `signedPdfUrl` | Link to the signed PDF |
| `completedAt` | When the document was signed or accepted |
| `signers` | Name, email and signing time of each signer |
| `fieldValues` | What the signers filled in while signing (text, checkboxes, dates) |
| `sourceData` | The data the document was made from |
| `webhookParams` | Your own parameters and the record id |

An Airtable, Notion or SmartSuite run adds the record id as `recId`, a ClickUp run as `taskId` and a Google Sheets run as `rowNumber`. With the API you add your own keys in `webhookParams`.

The signed event includes signer names and emails, the values signers entered, and the data the document was made from. Your Claude or ChatGPT account receives all of it, so the agent works with the same personal data as the document. Start an agent only where your team may use these AI tools for this data.

All fields of each event are on the [Notify Webhook](/features/actions-after-document-generation/notify-webhook#webhook-events) page.

## Your token stays with DocsAutomator

- The token is stored encrypted. The card shows it only as dots ending in its last 4 characters.
- You enter the token only in the DocsAutomator app.
- The token is sent only to the address it was saved for. If the trigger URL changes to another address, paste the token again and save.
- To replace the token, paste a new one and save. To stop, remove the Notify Webhook action.

## When Send test fails

| Message | What to do |
|---------|------------|
| Not accepted. Check the URL and the token. | Copy the URL and the token again and paste them. Each field saves a moment after you paste. |
| Not accepted. The token may have expired. | Create a new access token in ChatGPT and paste it into the card. |
| Not found. Check the URL. | Copy the trigger URL again from Claude or ChatGPT and paste it. |
| The agent could not start. | In ChatGPT, turn on workspace agents, save the agent, and make sure the workspace has credits. |
| The routine could not start. | In Claude, open the routine and resume it. |
| The other service had a problem. | Wait a few minutes and try again. |
| Too many runs right now. | Wait a few minutes. A Claude routine accepts up to 30 runs an hour. |

## Limits

- A Claude routine accepts up to 30 runs an hour, and a Claude account up to 100 API runs an hour. Each run uses your Claude plan's usage.
- DocsAutomator sends the event once and does not retry. One document starts one run.
