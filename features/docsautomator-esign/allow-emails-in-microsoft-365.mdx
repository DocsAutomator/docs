Microsoft 365 sometimes quarantines signing, acceptance and approval emails from DocsAutomator. This can happen even though the emails pass SPF, DKIM and DMARC. Usually only an admin of the recipient's Microsoft 365 tenant can release these emails and allow future ones.

## The emails to allow

| Item | Value |
|------|-------|
| From address | `sign@esign.docsautomator.co` |
| Sender domain | `esign.docsautomator.co` |
| Return-Path domain | `pm-bounces.esign.docsautomator.co` |
| DKIM signing domain | `esign.docsautomator.co` |
| Links in the email | `app.docsautomator.co` and `docsautomator.co` |

- Our DMARC policy is `reject`.
- Our email delivery service sends from a shared pool of IP addresses. Allow by domain, not by IP address.
- Other DocsAutomator product emails come from `emails.docsautomator.co`. These are `notifications@`, `docs@`, `errors@` and `invites@`. Team invitations come from `invites@`.

<Note>
A workspace can send signing emails from its own connected mailbox. Those emails come from that mailbox, not from DocsAutomator. This page does not cover them.
</Note>

## 1. Check quarantine

You likely have a quarantined email when both of these are true:

- A signer, approver or recipient did not get the email.
- In DocsAutomator, the document shows the email as sent.

<Steps>
  <Step title="Open quarantine">
    In the [Microsoft Defender portal](https://security.microsoft.com), go to **Email & collaboration** > **Review** > **Quarantine**. Stay on the **Email** tab.
  </Step>
  <Step title="Find the message">
    Look for a message from `sign@esign.docsautomator.co` to the person who did not get it.
  </Step>
  <Step title="Note the quarantine reason">
    Open the message and note its **Quarantine reason**.
  </Step>
</Steps>

The quarantine reason is usually **Spam**, **Phishing** or **High confidence phishing**. The **Phishing** reason includes spoofing and impersonation. To see the exact verdict, select **View message headers**. Find the `CAT` field in the `X-Forefront-Antispam-Report` header.

| `CAT` value | Verdict | Sections to follow |
|-------------|---------|-----------------|
| `BULK` | Bulk | 2 and 3 |
| `SPM` | Spam | 2 and 3 |
| `HSPM` | High confidence spam | 2 and 3 |
| `PHSH` | Phishing | 2 and 3 |
| `HPHSH` or `HPHISH` | High confidence phishing | 2 and 3 |
| `SPOOF` | Spoofing | 2 and 3 (Spoofed senders tab) |
| `UIMP`, `DIMP` or `GIMP` | Impersonation | 2 and 4 |

## 2. Release the message and report it as clean

<Steps>
  <Step title="Release the message">
    In quarantine, select the message and select **Release**. Microsoft delivers it to the recipient's inbox.
  </Step>
  <Step title="Open Submissions">
    In the Defender portal, go to **Actions & submissions** > **Submissions**. Open the **Emails** tab and select **Submit to Microsoft for analysis**.
  </Step>
  <Step title="Identify the message">
    Upload the message as an `.eml` or `.msg` file, or enter its network message ID. For a quarantined message, the ID is in the `X-MS-Office365-Filtering-Correlation-Id` header. Choose the recipient who did not get the email.
  </Step>
  <Step title="Report it as clean">
    Under **Why are you submitting this message to Microsoft?**, select **I've confirmed it's clean**. Select **Next**.
  </Step>
  <Step title="Allow the message">
    Select **Allow this message**. Keep **Remove allow entry after** at **45 days after last used date**. Select **Submit**.
  </Step>
</Steps>

This adds an allow entry for the sender to the Tenant Allow/Block List. Section 3 shows which tab it goes to.

For an impersonation verdict, the submission creates no Tenant Allow/Block List entry. Microsoft may add the sender to the trusted senders of the anti-phishing policy. Check this in section 4.

<Warning>
An allow entry for a domain or email address expires. Microsoft removes it 45 days after it was last used. If our emails are quarantined again after that, repeat this section with the new message.
</Warning>

## 3. Check the Tenant Allow/Block List

In the Defender portal, go to **Email & collaboration** > **Policies & rules** > **Threat policies**. In the **Rules** section, select **Tenant Allow/Block Lists**.

The entry from section 2 shows here after a few moments. The tab depends on the verdict.

### Spam, bulk and phishing

Open the **Domains & addresses** tab. The entry for `sign@esign.docsautomator.co` or `esign.docsautomator.co` is here.

You can also add an entry on this tab directly. Select **Add** > **Allow**. Enter `esign.docsautomator.co` or `sign@esign.docsautomator.co`. Microsoft allows this for bulk, spam, high confidence spam and phishing verdicts. For high confidence phishing, you must use a submission as in section 2.

An entry you add here also expires 45 days after it was last used.

### Spoofing

If spoof intelligence blocked the message, the submission adds the entry to the **Spoofed senders** tab. It does not go to the **Domains & addresses** tab. Entries on the **Spoofed senders** tab never expire.

You can also add an entry on this tab directly. Select **Add**. Enter the domain pair `sign@esign.docsautomator.co, esign.docsautomator.co`. The second value is our DKIM signing domain. Set **Spoof type** to **External** and **Action** to **Allow**. Select **Add**.

If no entry shows up after a submission, add one directly as described above.

## 4. Allow the sender for impersonation verdicts

Impersonation verdicts come from the anti-phishing policy in Microsoft Defender for Office 365. The Tenant Allow/Block List entries in section 3 do not cover them.

<Steps>
  <Step title="Open the anti-phishing policy">
    In the Defender portal, go to **Email & collaboration** > **Policies & rules** > **Threat policies**. In the **Policies** section, select **Anti-phishing**. Select the policy named in the **Policy name** field of the quarantined message.
  </Step>
  <Step title="Edit the protection settings">
    In the details, select **Edit** in the **Phishing threshold & protection** section.
  </Step>
  <Step title="Add a trusted sender or domain">
    Select the **Manage trusted sender(s) and domain(s)** link. Add `sign@esign.docsautomator.co` on the **Sender** tab, or `esign.docsautomator.co` on the **Domain** tab. Save your changes.
  </Step>
</Steps>

If the policy is the Standard or Strict preset policy, you cannot edit it here. Select **View preset security policies** and change it on the **Preset security policies** page.

## 5. If it still happens

Email [support@docsautomator.co](mailto:support@docsautomator.co) with:

- The quarantine reason.
- The recipient's address and the date the email was sent.
- The full `X-Forefront-Antispam-Report` header of the message. In quarantine, select the message and select **View message headers** to copy it.
