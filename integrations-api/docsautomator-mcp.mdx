Connect DocsAutomator to AI assistants like Claude, Cursor, and other MCP-compatible clients. Generate documents, manage automations, and handle e-signatures directly from your AI conversations.

## What is MCP?

The Model Context Protocol (MCP) is an open standard that allows AI assistants to securely connect to external tools and data sources. With the DocsAutomator MCP server, you can:

- Build complete automations: generate Word templates with AI, connect data, map fields, and configure the output
- Generate documents from your automations
- List and manage automations
- Check document generation status
- View and manage e-signature sessions
- Extract placeholders from templates, with per-placeholder descriptions for AI clients

## Multi-Workspace Accounts

If your DocsAutomator account belongs to more than one workspace and you connect through OAuth (Claude Desktop, ChatGPT, and other OAuth-based MCP clients), the authorization screen shows a workspace picker. The connection is bound to the workspace you select, and only that workspace's automations are reachable through it.

To change which workspace an existing connection points at, disconnect the integration in your AI client and reconnect. That triggers a fresh OAuth flow and lets you pick a different workspace.

API key connections (the Claude Code CLI with an API key, custom clients) are bound to the workspace of the key itself, so no picker is involved; switch workspaces by using a different API key.

## Setup by Client

### Claude Desktop

1. Open Claude Desktop
2. Click the **+** button in the conversation
3. Select **Connectors** → **Add custom connector**
4. Enter the MCP server URL:
   ```
   https://mcp.docsautomator.co/mcp
   ```
5. Click **Connect**
6. Sign in to DocsAutomator and authorize access

Once connected, you can ask Claude things like:
- "List my DocsAutomator automations"
- "Generate a document using automation [ID] with this data..."
- "Check the status of my e-signature sessions"

---

### Claude Code (CLI)

Add DocsAutomator to Claude Code with a single command:

```bash
claude mcp add docsautomator -t streamable-http -e API_KEY=YOUR_API_KEY -- https://mcp.docsautomator.co/mcp
```

Replace `YOUR_API_KEY` with your [DocsAutomator API key](https://app.docsautomator.co/settings/workspace/api).

#### Alternative: Manual Configuration

Add to your `~/.claude/settings.json`:

```json
{
  "mcpServers": {
    "docsautomator": {
      "url": "https://mcp.docsautomator.co/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}
```

<Warning>
A ChatGPT Business or Enterprise subscription is required to use MCP connections with ChatGPT. Additionally, Developer Mode must be enabled in your ChatGPT settings.

3. Enable **Developer Mode** if not already enabled

6. Enter the following configuration:
   - **Name:** DocsAutomator
   - **Server URL:** `https://mcp.docsautomator.co/mcp`
   - **Authentication:** OAuth
   - Leave Client ID and Secret blank
7. Click **Create**

Once connected, you can ask ChatGPT to generate documents, manage automations, handle e-signatures, and more using natural language.

## Available Tools

The MCP server gives your AI client 18 tools. Your AI client sees each tool with its full instructions after it connects.

The main path: your AI client is the data source. It reads the placeholders with `get_automation` and sends the values with `create_document`. Record sources such as Airtable or Notion are an optional second setup.

### Automations

| Tool | Purpose |
|------|---------|
| `list_automations` | List your automations, with each automation's description when set |
| `get_automation` | Read one automation: template, placeholders with their meaning and print format, data source, field mappings, output and signing settings. On request it adds the exact trigger setup for its data source, or the text of a Google Doc template |
| `create_automation` | Create an automation, start one from another automation's template, or copy a whole automation |
| `configure_automation` | Name, description, status (live, test, inactive or trash), document name field, locale, time zone, date format, and automatic triggers for record sources |

### Templates

| Tool | Purpose |
|------|---------|
| `generate_word_template` | Design a new Word template with AI, in your brand when you give your website |
| `edit_word_template` | Change the Word template with an instruction (layout, styling, placeholders, logo), or undo the last AI change |
| `set_template` | Use a gallery template, your own Word or PDF file, or a Google Doc you already have |
| `search` | Search the DocsAutomator documentation or the template gallery |

### Placeholders

| Tool | Purpose |
|------|---------|
| `configure_placeholders` | Store what each placeholder means and how it prints (currency, decimals, dates), options such as removing an empty line, and show and hide rules for sections and placeholders |
| `configure_line_items` | Grouping, sorting, an auto-number column, and repeating section options |

### Record sources (optional)

| Tool | Purpose |
|------|---------|
| `get_data_source` | Browse the tables and fields of a connected Airtable, Notion, Google Sheets, Google Forms, SmartSuite or ClickUp account |
| `set_data_source` | Connect a record source (including line item tables) and map placeholders to its fields in one call, checked against the live schema |

### Output and documents

| Tool | Purpose |
|------|---------|
| `configure_output` | Email, PDF to Google Drive or OneDrive, Word and Google Doc copies, PDF merge, webhook, and write-back fields |
| `create_document` | Make a document |
| `get_recent_runs` | Recent runs with their real error messages, or the status of one queued document |

### Acceptance and signature

| Tool | Purpose |
|------|---------|
| `configure_esignature` | Acceptance or signature, signers, order, reminders, email copy, and where the signed PDF goes |
| `list_esign_sessions` | List requests with their status and who has not signed or accepted yet; one request in full with its signing links and audit trail |
| `manage_esign_session` | Remind or re-invite one recipient, or cancel a request |

<Note>
Record source accounts (Airtable, Notion, Google, and the others) use OAuth and are connected once in the DocsAutomator app under **Settings → Integrations**. When an account is not connected, the tools answer with the link to that page. All other setup steps work through MCP.
</Note>

### Descriptions for AI Clients

Two description fields help an AI client work with your automations without extra prompt engineering:

- **Automation description:** a note on what the automation is for and what data it needs. Set it in the app under **Automation Settings → Description**, or with `configure_automation`. `list_automations` returns it, so the AI picks the right automation.
- **Placeholder descriptions:** what each placeholder means and how it prints (for example "Subtotal before tax, in EUR; prints as 1.234,56 €"). Set them with the gear icon next to a mapping, or with `configure_placeholders`. `get_automation` returns them (the REST API too), so the AI knows what data belongs in each placeholder.

DocsAutomator formats every value itself, so an AI client sends raw values: numbers as numbers and dates as ISO dates (2026-10-01).

**Example prompt:**
> "Describe the placeholders of automation abc123 so my CRM agent can fill them."

### Make a document

`create_document` parameters:
- `automationId` (required): the automation ID
- `mode`: `preview` (a watermarked PDF, nothing sent), `test` (outputs run in test mode) or `live` (a real document)
- `data`: placeholder values, sent raw
- `recId`: the record ID for Airtable, Notion, SmartSuite and ClickUp automations
- `rowNumber`: the row number for Google Sheets automations
- `documentName`: a custom name for the document
- `async`: if true, answers at once with a job ID; follow it with `get_recent_runs`
- `recipients`: who signs or accepts this document, for example `[{ "signer": 1, "email": "anna@acme.com", "name": "Anna Weber" }]`
- `skipEsign`: if true, makes the document without starting signing or acceptance

**Signing and acceptance:** if the automation has signing or acceptance turned on, `create_document` starts it. The answer includes the session and its signing links.

**Recipients named in chat:** the assistant always passes `recipients` when a document goes out for signing or acceptance. When you tell the assistant who should sign or accept ("send quote 12 to Anna at anna@acme.com"), it passes that person in `recipients`. This works for every data source, including Airtable, Notion, Google Sheets, SmartSuite and ClickUp automations called with a record ID, and you do not need a second automation to send from chat. A listed signer's email and name replace the saved ones for that one document; the automation itself does not change. `signer` is the signer's number from `get_automation`. It can be left out when the automation has exactly one signer and is needed when it has two or more.

When the assistant sets up signing or acceptance with `configure_esignature`, it follows these defaults:
- On API and MCP automations, and automations without a data source, every signer is "given with each request", so each send names the person in `recipients`.
- On Zapier, Make, n8n, Glide and Noloco automations, the signer uses a template placeholder, because their apps do not send recipients with each run.
- On Airtable, Notion, Google Sheets, SmartSuite, ClickUp and Google Forms automations, the signer points at the record's email field, because their triggers run without anyone naming a recipient.

**Test mode:** the first document of a new setup is sent in test mode. A test mode signing or acceptance request sends the real email to the real person and is never billed.

**Example prompts:**
> "Create a document using automation abc123 for Acme Corp, dated today."
>
> "Send the quote for record rec123 to Anna Weber at anna@acme.com for acceptance."
>
> "Who has not accepted their quote yet? Remind them."

## Troubleshooting

### "Authentication required" error
- Ensure your API key is valid and active
- Check that the Authorization header is formatted correctly: `Bearer YOUR_API_KEY`
- Verify your API key at [DocsAutomator Settings](https://app.docsautomator.co/settings/workspace/api)

### "Automation not found" error
- Verify the automation ID is correct
- Ensure the automation belongs to your workspace
- Check that the automation is not deleted

### E-signature not starting
- Verify the automation has e-signing enabled in its output settings
- Check that signer emails are configured in the automation
- Ensure the e-signature placeholders exist in the template

### Rate limiting
- Document generation: 2000 requests per 15 minutes
- If you hit limits, wait for the reset period
