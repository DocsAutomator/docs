## Problem

When generating documents via an Airtable automation script, requests that exceed 120 seconds fail with an error. This is an Airtable platform limitation on automation script execution time.

<Warning>
Airtable enforces a 120-second (2 minute) execution limit on all automation scripts. Complex documents may exceed this limit.
</Warning>

## Solution

Use Auto Create instead of a script. Auto Create runs in DocsAutomator, not in Airtable, so the script time limit does not apply.

<Steps>
  <Step title="Open Auto Create">
    Open **Auto Create** on the automation page.
  </Step>
  <Step title="Turn on Auto creation">
    Turn on **Auto creation**, then pick the field, the condition and the value, for example Status equals Approved.
  </Step>
  <Step title="Turn off the Airtable automation">
    Turn off the Airtable automation that runs the script, so a record does not create two documents.
  </Step>
</Steps>

### Advanced: keep your script and send `async: true`

If you need to keep the script, add `async: true` to the request body. DocsAutomator then answers at once with HTTP 202 and a `jobId`, and the script ends long before the limit.

```javascript
body: JSON.stringify({
    recId: input.config().recId,
    docId: 'YOUR_AUTOMATION_ID',
    async: true
})
```

The script no longer gets the link. DocsAutomator saves the PDF to the record when it is ready, in the attachment field or the PDF URL field set in your automation. Errors show on the [Documents](https://app.docsautomator.co/documents) page, because the script no longer sees them.

## How It Works

With Auto Create, when a record changes to match your condition, Airtable tells DocsAutomator, and DocsAutomator creates the document. No script waits for the document, so there is no time limit to hit.

<Info>
Auto Creation works on every Airtable plan, including Free. See the [Airtable integration guide](/integrations-api/airtable) for the fields and conditions you can use.
</Info>
